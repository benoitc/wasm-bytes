Write a complete web page, as one HTML file, that demonstrates a sound
effect recovered from the game DX-Ball (1996).

A ball moves across the screen and a short beep follows it from left to
right. A WebAssembly function decides where each beep sounds. The page is
given two versions of that function: "Original" places the sound on the
ball's side, and "Reversed" places it on the opposite side. The person
using the page switches between them and hears the difference.

What the page receives

A script named modules.js, in the same folder as the page, defines:

  window.PAN_MODULES = {
    original: { label: "Original", model: "...", reply: "...", sha256: "...", bytes: "..." },
    reversed: { label: "Reversed", model: "...", reply: "...", sha256: "...", bytes: "..." }
  };

Each "bytes" field is a complete WebAssembly module, encoded in base64.
Each module exports one function, screen_pan(x). It takes an integer x
from 0 at the left edge through 640 at the right edge, and returns an
integer from -500 to 500. Load the script with
<script src="modules.js"></script>, instantiate both modules with the
WebAssembly JavaScript API, and call screen_pan on the selected one.

What the page does

- A ball moves across a horizontal track from left to right, again and
  again. Its position is an integer x from 0 through 640.
- While the sound is on, the page plays a short beep every 200 ms. The
  pan of each beep comes from the value v that screen_pan(x) returns for
  the ball's position at that moment. Use the Web Audio API and a
  StereoPannerNode whose pan is v / 500, so that -500 is fully left and
  500 fully right.
- Every beep is the same in both modes: same pitch, same volume, same
  length. Switching modes changes nothing but which module's screen_pan
  the page calls.
- Beside the ball, the page shows the current x and the value
  screen_pan(x) returned, so that someone with the sound off can follow.
  When the ball is paused and the person switches modes, the shown value
  is the selected module's value for that x.
- The page never computes the pan itself. Every value it shows or plays
  comes from calling screen_pan on the selected module.

Controls

Use these exact element ids, so that the page can be tested
automatically:

  id="sound"          a button: one tap or click turns the sound on, the
                      next one turns it off

                      When the user taps Sound to turn it on, request media
                      playback before starting the beeps. If
                      navigator.audioSession is available, set
                      navigator.audioSession.type = "playback" inside that
                      click handler. Then create or resume the audio
                      context. Browsers without that API should still start
                      the beeps normally. A second tap stops them.
  id="mode-original"  a button that selects the Original module
  id="mode-reversed"  a button that selects the Reversed module
  id="pause"          a button that pauses and resumes the ball
  id="reading"        the element that shows x and screen_pan(x)

How the page looks

Lay the page out as one column, at most 760 px wide, centred, with 16 px
side margins. From top to bottom:

- Colors. A light page by default, and a dark one when the system prefers
  it (prefers-color-scheme: dark):

                  light      dark
    background    #f7f6f2    #161615
    text          #1d1d1b    #ecebe6
    muted text    #6b6a66    #a3a19a
    panels        #ffffff    #20201e
    lines         #d9d6ce    #3a3935
    ball          #c2410c    #fb923c
    accent        #1d4ed8    #93b4ff

  Text uses the system font at 16 px, with a line height of 1.5.
- A heading, then a short paragraph saying what to do: turn the sound on,
  watch the ball move from left to right, and switch between Original and
  Reversed to hear the beep move the other way.
- One row of controls, which wraps on a narrow screen: the Sound button,
  labelled "Sound: off" or "Sound: on"; then Original and Reversed, joined
  as one segmented control; then Pause, labelled "Pause", or "Play" while
  the ball is paused. Buttons have the panel color, a 1 px border in the
  line color and 8 px rounded corners. In the segmented control, the
  selected button is filled with the accent color, with its text in the
  background color.
- One line of muted text under the controls: use headphones to hear left
  and right, since a phone's speakers barely separate them.
- The stage: a panel 150 px tall and as wide as the column, with a 1 px
  border and 10 px rounded corners. Small muted labels along its top read
  "x = 0" at the left, "320" in the middle and "640" at the right. The ball
  is a 22 px circle in the ball color, 62 px below the top of the stage.
  Its centre is 16 px from the left side at x = 0 and 16 px from the right
  side at x = 640, and in proportion in between. The reading sits under
  the ball, on two centred lines in a monospace font:

    x = 394
    screen_pan(x) = 115

  It follows the ball, but never goes past either side of the stage.
- Under the stage, a meter: a bar 10 px tall with rounded ends, in the
  line color. A marker 4 px wide and 18 px tall, in the accent color, sits
  at 50% + 50% * v / 500 of the bar's width, where v is the value in the
  reading: at the left end for -500, the middle for 0, the right end for
  500. Under the bar, three small muted labels: "left" at the left, "stereo
  position sent to the speakers" in the middle, and "right" at the right.
- Last, a section that starts collapsed, titled "Inspect the two files
  this page loaded". It holds a table with one row per module: its label;
  its model and reply from modules.js; and the SHA-256 recorded in
  modules.js. Where the browser allows it, compute the SHA-256 of the bytes
  the page loaded, and say whether it matches the recorded one. Let long
  values wrap, so that nothing scrolls sideways on a phone.

Requirements

- It works in current desktop browsers and in Safari on an iPhone,
  including when the iPhone's silent switch is on.
- It makes no network requests and uses no libraries. All HTML, CSS and
  JavaScript are in this one file, apart from modules.js.
- It is readable on a phone, without scrolling sideways.

Reply with only the HTML document, starting with <!doctype html>. Do not
add any explanation or code fence: the reply is saved as index.html and
opened as it is.
