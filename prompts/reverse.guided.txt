Below is a complete WebAssembly module in the binary format, as hex. It
exports one function, named "screen_pan", with one i32 parameter and one i32
result. The function turns a horizontal screen position x, from 0 at the
left edge through 640 at the right edge, into a stereo pan value: negative
is left of centre, positive is right of centre.

Change the module to reverse the stereo: for every x, screen_pan(x) must
return the value it returns now with its sign reversed. A position on the
left of the screen then sounds on the right, a position on the right sounds
on the left, and the centre stays at 0.

Keep the function's name, parameter and result. Keep the module's shape:
exactly one function, the exported one, nothing else exported, no imports,
no memory and no start function.

Reply with the complete revised module. You write every byte: the magic
number and version, every section id, every section length, every function
body length, every local declaration and every instruction. Nothing will be
added to your bytes and no length will be corrected: the bytes you send are
the bytes that run.

Work through these steps before you reply. Your reply contains only the
final bytes.

1. Write the function as WebAssembly instructions, one per line, using the
   names in the instruction table below. After each instruction, note what
   is on the stack. The function must end with exactly one i32 on it.
2. Decide which locals the function needs besides its parameter. The
   parameter is local 0; locals you declare are numbered after it.
3. Encode each instruction: its byte from the table, then its immediate.
   A local index or a label depth is an unsigned LEB128 number, an
   i32.const value is a signed LEB128 number, an f64.const value is the
   eight bytes of a double, a block type is one byte.
4. Build the function body: the local declarations, the instruction bytes,
   and 0b for the end of the function. Count its bytes.
5. Build each section: its id, the size of its contents in bytes, then the
   contents. Count each section again.
6. Put the header and the sections together, in the order type, function,
   export, code. Count the total, then reply with the bytes.

Module layout

  header            00 61 73 6d 01 00 00 00
  section           id byte, size of the contents (unsigned LEB128), contents
  vector            count (unsigned LEB128), then the items
  type section      id 01: a vector of function types. A function type is
                    60, a vector of parameter types, a vector of result
                    types. i32 is 7f, f64 is 7c.
  function section  id 03: a vector of type indices, one per function.
  export section    id 07: a vector of exports. An export is the name's
                    length, the name's bytes, 00 for a function, and the
                    function's index.
  code section      id 0a: a vector of function bodies. Each body is its
                    size in bytes, then a vector of local groups (a count
                    and a type, such as 02 7f for two i32 locals or 01 7c
                    for one f64 local), then the
                    instructions, then 0b.

Numbers

  Unsigned LEB128 (sizes, counts, indices, label depths): take the number 7
  bits at a time, lowest bits first, and add 80 to every byte except the
  last. 5 is 05, 200 is c8 01.
  Signed LEB128 (i32.const): the same, but stop only when the bits left are
  all 0 and the last byte's 40 bit is clear, or the bits left are all 1 and
  that bit is set. 3 is 03, 63 is 3f, 64 is c0 00, 127 is ff 00, 128 is
  80 01, 300 is ac 02, -1 is 7f, -64 is 40, -65 is bf 7f.
  Doubles (f64.const): the eight bytes of an IEEE 754 double, lowest byte
  first. A double is a sign bit, an 11-bit exponent biased by 1023, and a
  52-bit fraction, so the last two bytes hold the sign, the exponent and the
  top of the fraction. 2.0 is 00 00 00 00 00 00 00 40, 0.5 is
  00 00 00 00 00 00 e0 3f, 0.25 is 00 00 00 00 00 00 d0 3f, 1.75 is
  00 00 00 00 00 00 fc 3f, 100.0 is 00 00 00 00 00 00 59 40, -3.0 is
  00 00 00 00 00 00 08 c0.

Instructions

  In the stack column, b is the value pushed last. A comparison pushes 1
  for true and 0 for false. A block type is 40 for no result, 7f for one
  i32 result. Label depth 0 is the innermost enclosing block, loop or if,
  1 the one around it, and so on. A branch to a loop goes back to its
  start; a branch to a block or an if goes past its end.
