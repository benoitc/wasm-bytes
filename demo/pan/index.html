DX-Ball sound pan, written as WebAssembly bytes

A ball crosses the screen. Each beep is panned by screen_pan(x), the position-to-pan helper that REA recovered from DX-Ball's x86 code, here implemented by a model as raw WebAssembly bytes. Switch modules to hear the same motion with the stereo reversed.

Where each part comes from

REA recovered the behaviour: the 63-byte function at 0x406400 in DXBALL.EXE 1.07 computes (x × 1.5625 − 500.0) × scale with the scale stored as 1.0, then truncates toward zero. The game passes it a screen position and gives the result to its sound routine.

The model wrote both modules, every byte, from an English description of that behaviour and, for the reversed one, its own accepted bytes and a change request. The runner checked each one on every position from 0 through 640 before this page was built.

This page is the host. It moves the ball, calls screen_pan(x) on the selected module, and plays the same beep at the same volume and times in both modes. It maps the returned value to the speakers as value ÷ 500, so −500 is fully left and 500 fully right. That mapping is the host's choice: the game's own sound code has not been reconstructed, so how loud DX-Ball made each side is not known.
